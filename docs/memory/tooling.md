# Tooling, CI and the portfolio standard

Read when you touch `package.json`, the lockfile, `.nvmrc`, Biome, Vitest and its thresholds, `.github/` (CI, Dependabot, the release and registry workflows), `.gitignore`, `scripts/icons.ts`, or anything the portfolio standard governs. The decisions this file points at are rows of `docs/decisions.md`; the standard itself is `COMMON-PROJECT-SPEC.md` in the private `second-brain` repository, and it is never edited from here.

## The toolchain as it stands

- 2026-10-19 (rev. 2026-10-24) — **npm, one lockfile** (`package-lock.json`); Node 26 from `.nvmrc` (24 until 2026-10-24, moved with the portfolio's C14), `engines` at ≥ 22 as the floor, `@types/node` held to the `.nvmrc` major by Dependabot (D121, D27). No container image: the Worker and GitHub Pages are the deploys. **How to apply**: a Node bump moves `.nvmrc`, `@types/node` and the `CLAUDE.md` line together; never a second lockfile.
- 2026-10-19 — **The gate is `npm run check`** — Biome, `tsc` on the app, the Worker and the service worker, Vitest, the Vite build; CI's `verify` job runs the same with coverage, `src/core` at ≥ 90 % lines, functions and statements and ≥ 75 % branches (D26) — and **`npm run e2e`** after a change to the UI, the Worker or the service worker (CI's `e2e` job, D134). `node .github/release.mjs check` holds `CHANGELOG.md` to `package.json` on every pull request (D123); `registry.yml`'s `check` job refuses a Registry block that would leak in this public repo (D122). Pages and Cloudflare deploy from `main` only once both jobs pass (D27, D60).
- 2026-10-21 — **Dependabot follows C20 (D135)**: `.github/dependabot.yml` is the portfolio's template trimmed to npm at `/` and GitHub Actions (no Dockerfile, so no `docker` block). Families kept for a major: `vite` + `@vitejs/*`, `vitest` + `@vitest/*`, `@biomejs/*`, `@playwright/test` + `playwright-core` (both pinned exact, they must move together; their minors share the `minor-and-patch` pull request), `@fontsource/*` + `@fontsource-variable/*`. Kept `ignore`: `@types/node` majors (D121); none held for the toolchain. **How to apply**: a red Dependabot pull request is fixed in a pull request of its own or held by a commented `ignore` and closed, never merged red, never pushed to; a new family whose packages only work in step goes above `minor-and-patch`.
- 2026-10-21 — **A named control's visible text must sit inside its name (WCAG 2.5.3, axe's `label-content-name-mismatch` since 4.14).** axe counts every glyph on screen, `aria-hidden` ones too, and glues adjacent spans without a space: the brand's "vs" mark made "vsVersus", a card's A/B tag "ACroissant". **How to apply**: a decorative glyph inside a control with an `aria-label` is drawn with CSS, `content: 'A' / ''` (empty alternative, an `@supports not` fallback without it), never written in the markup — `.brand-mark` and `.side-tag` do so; and the `aria-label` says every word the control shows (a color card's name adds its code).
- 2026-10-19 — **Biome 2 lints and formats** (`biome.json`); `npm run format` fixes. Markdown is outside its reach, so `MEMORY.md` and `docs/` are checked by eye.
- 2026-10-19 — **TypeScript 7 runs every type check**, strict with `noUncheckedIndexedAccess`, in three projects (the app, `worker/`, `src/sw/`). No TypeScript 6 alias: nothing here needs the old compiler API.

## The portfolio standard

- 2026-10-19 — **The portfolio standard (`COMMON-PROJECT-SPEC.md` C14–C19, validated 2026-10-19) applied.** In force here: one package manager and one lockfile, Node 24 pinned by `.nvmrc` with `engines` ≥ 22 and no container image to tag (C14, N1); TypeScript 7 for every type check, no 6 alias (N2); Biome in the pull-request gate (N3); `ci.yml` on `pull_request` and `main` with coverage and both end-to-end suites, Dependabot grouped with `@types/node` held to `.nvmrc` (C15); no tracked secret, `.gitignore` covering `.env*` but the public `.env.worker`, the Worker's secrets in Cloudflare only, security headers from `build/seo.ts` with the CSP reported only (C16); SEO from one build-time module, `llms.txt`, a social card per language, the legal notice holding the measurement switch, Umami from `insight.steevepommier.com`, English and French with parity tests, axe and token-contrast tests, light and dark themes, the icon set, the version shown (C17, C11, C13); the visitor's data backed up by export and import (C18); a fiche in the register and a page on steevepommier.com (C19). What this adoption added: the agent scaffold, the `.gitignore` rules and the three missing icons — the bullets below. Not applicable: Docker tags. (The secrets' template was judged n/a here, then added on 2026-10-22: entry below.) Left open: a backup of the Worker's data (`MEMORY.md`, open items).
- 2026-10-19 — **The agent scaffold** of `COMMON-PROJECT-SPEC.md` §3 landed: `MEMORY.md` as the index over the `docs/` files this project kept from the start, this folder for new topics, the canonical `/memorize` (`.claude/commands/memorize.md`, the spec's text byte for byte), `AGENTS.md` as a symlink to `CLAUDE.md`, and `CLAUDE.md` in the standard shape (rules 1 to 4, the trust-the-disk section). Two rules it brought that the repo had not stated: a commit ends with whatever attribution trailer the harness asks for, never a spelling of the repo's own (K2); and memory points at D rows rather than restating them, the whole-tree facts (code map, conventions, domain rules) staying in `CLAUDE.md` as its Context. **How to apply**: a new rule of the standard reaches this repo by being pasted into `CLAUDE.md` in a normal commit.
- 2026-10-19 — **`.gitignore` covers the local env files and the IDE folders** (`.env`, `.env.local`, `.env.*.local`, `.idea/`, `.vscode/`; C16). `.env.worker` stays tracked on purpose: it holds the Worker build's public `VITE_API_URL` and nothing else, and its header says so. A `VITE_` value ends up in the browser bundle anyway, so a secret can never go in an env file the build reads — the Worker's secrets go through `wrangler secret put` (locally `.dev.vars`, ignored).
- 2026-10-22 — **The Worker's secrets have a tracked template, `worker/.dev.vars.example`** (G3 of the portfolio audit, which accepts `.dev.vars.example` at any depth): `ADMIN_TOKEN`, `TURNSTILE_SECRET`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, each empty with what it does and how to make it. It sits in `worker/`, not at the root, because Wrangler reads `.dev.vars` from the config file's folder (`-c worker/wrangler.jsonc`) — a root `.dev.vars` is silently ignored. Every secret is optional and an empty value means off (the Worker tests truthiness), so a copy of the template as is runs. The plain variables (`IMAGES_UPLOAD`, `CACHE_SECONDS`, `PUSH_LOCAL`, `BOARD_TTL_SECONDS`, `TEMPLATE_INDEX_VOTERS`) are not keys there: not secrets, none declared in `wrangler.jsonc`, documented in `worker/src/env.ts`. **How to apply**: a new secret in `Env` gets its line in the template, in `wrangler.jsonc`'s closing comment and in `docs/online-architecture.md` step 4, in the same commit; `.gitignore`'s `.dev.vars` matches the exact name only, so the template is never ignored (`git check-ignore` says so).
- 2026-10-19 — **The icon set is the portfolio's (C11)**: `favicon-16.png` and `favicon-32.png` for the tab, `icon-maskable-192.png` beside the 512, and the touch icon written as RGB (`opaquePng` in `scripts/icons.ts`, which refuses a translucent pixel), the rest of the set as before (`docs/seo.md`). Three traps: `tests/seo.test.ts` held every declared PNG favicon to a multiple of 48 px, Google's rule when the SEO pass was written — Google now asks for a square of at least 8 px and recommends more than 48, so the 16 and 32 px favicons are declared and the test holds the multiples of 48 for the larger ones only; resvg writes RGBA whatever the drawing, so an opaque PNG needs its own encoder (`node:zlib`'s `deflateSync` and `crc32`, no dependency); and `npm run icons` rewrites every file, whose bytes shift from one machine to the next at equal dependency versions (satori's path numbers, resvg's PNG encoder) — stage only the files you meant to change, and give a redesigned icon a new name (D68).
- 2026-10-24 — **Running `npm run e2e` in a cloud container**: the container's Chromium (`/opt/pw-browsers/chromium`, build 1194) is not the one `@playwright/test` 1.64.1 pins (1248), and `CHROMIUM_PATH` only reaches the worker projects, so the `tests/e2e` projects fail to launch. **How to apply**: run once with a throwaway config that spreads `playwright.config.ts` and sets `launchOptions.executablePath` (and `channel: undefined`) on every project, then delete it; CI is unaffected (`npx playwright install --with-deps chromium`). Two other things seen on Node 26 / npm 11.20 that are not regressions: npm warns that the `esbuild` and `workerd` install scripts are "not yet covered by allowScripts" (the platform binaries come from their optional packages: the build and the workerd suites pass either way), and `worker.test.ts` › "counts an IPv6 address by its /64" can fail once when its six publishes straddle the local rate limiter's 60 s window (`PUBLISH_LIMIT`), green on rerun.
